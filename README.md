# like_a_boss — openJiuwen Challenge 2026

Командный проект агента на openJiuwen. Агент должен выбирать и решать задачи, набирая максимум баллов за ограниченный бюджет токенов.

## Текущее состояние

Репозиторий: https://github.com/verrronikka/like-a-boss-openjiuwen. Есть первый прототип: загрузка задач, планировщик, цикл вызовов модели через openJiuwen, файловые инструменты, запуск Python и сохранение ответов. Качество решения задач настоящими моделями пока не измерено.

## Запуск без ключа

Из папки проекта в PowerShell:

```powershell
py -3.12 run_agent.py --tasks-dir examples/tasks --dry-run
```

Команда покажет порядок восьми примеров и оценки расхода, не вызывая модель и не меняя файлы. Планировщик делит награду на приблизительную стоимость по типу задачи и длине условия. Поля `expected` и `check` не используются при решении и не передаются модели.

## Файлы

| Файл | Назначение |
| --- | --- |
| `run_agent.py` | Параметры запуска |
| `harness.py` | Планировщик, бюджет, инструменты и цикл агента |
| `examples/tasks/` | Восемь примеров организаторов с эталонами для проверки |
| `tests/test_harness.py` | Проверки и локальный тестовый API |
| `scripts/import_examples.py` | Импорт исходного ZIP без файлов macOS |
| `.env.example` | Образец настройки доступа без настоящего ключа |

## Docker

```powershell
docker build -t like-a-boss-openjiuwen:dev .
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g -v "${PWD}/examples/tasks:/data/tasks:ro" like-a-boss-openjiuwen:dev --tasks-dir /data/tasks --dry-run
```

Для настоящего прогона активируйте приглашение NeuralDeep. Создайте локальный `.env` по образцу `.env.example`, вставьте API-ключ из кабинета. Docker получает его через `--env-file`; при прямом запуске Python программа читает переменные процесса, а не файл `.env`.

Проверяем на отдельной копии: агент меняет исходники задач на программирование. Команды ниже предполагают, что `runs/smoke` ещё не существует.

```powershell
New-Item -ItemType Directory -Force runs | Out-Null
Copy-Item -LiteralPath examples/tasks -Destination runs/smoke -Recurse
docker run --rm --read-only --tmpfs /tmp:rw,size=2g --cap-drop ALL --security-opt no-new-privileges --cpus 4 --memory 16g --pids-limit 512 --env-file .env -v "${PWD}/runs/smoke:/data/tasks:rw" like-a-boss-openjiuwen:dev --tasks-dir /data/tasks --limit 1 --budget 2000 --task-budget 1500
```

Настоящий прогон расходует квоту API. `run_python` исполняет код модели и не является отдельной песочницей: реальные задачи запускаем в Docker, монтируя только копию задач. Ограничение путей файловых инструментов не изолирует исполняемый Python-код.

## Параметры и результаты

`--model` выбирает одну из четырёх разрешённых моделей; по умолчанию `qwen3.8-27b-noreason`. `--budget` — общий лимит, `--task-budget` — лимит на задачу, `--max-steps` — число обращений к модели, `--max-output` — максимальный выход запроса. `--time-limit` задаёт общее время в секундах; по умолчанию 3300. `--limit` ограничивает число попыток. Полный список: `python run_agent.py --help`.

Расход: `input_tokens / 10 + output_tokens`; рассуждения входят в выход и повторно не прибавляются. Кеш не уменьшает входной расход. При отсутствии статистики API или ошибке запроса агент сохраняет прогресс и останавливается. Резерв перед запросом приблизительный; окончательный учёт ведёт прокси организаторов.

Бюджеты по умолчанию 20000 на весь запуск и 4000 на задачу выбраны для разработки и не являются официальными значениями соревнования.

Ответ атомарно сохраняется в `answer.txt` в корне задачи и дополнительно в `workspace`, если такая папка есть. Это временный способ учесть расхождение между регламентом и условиями примеров. Отчёт `agent-report.json` содержит статусы, расход и последовательность вызванных инструментов; путь меняется через `--report`. Статус `submitted` означает сохранение ответа, а не прохождение скрытых тестов.

Повторный запуск не восстанавливает бюджет из старого отчёта. Для измерений используйте новую копию задач. Полные сообщения для обучения оценщика пока не сохраняются. Зависимости скачиваются при сборке; при запуске дополнительные пакеты и веса не скачиваются. Логи SDK направлены в `/tmp`, поэтому `/app` может быть доступен только для чтения.

## Проверки программы

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Интеграционный тест использует настоящий SDK openJiuwen и локальный HTTP-сервер с заданными ответами. Он проверяет вызов Python-инструмента и сохранение ответа, не обращаясь к NeuralDeep. Остальные проверки охватывают бюджет, сохранение прогресса и файловые операции.

## План работы

1. Активировать приглашение NeuralDeep и измерить настоящий прогон одной задачи.
2. Проверить все восемь примеров, записывая расход, время и правильность ответов.
3. Улучшить оценки стоимости, распознавание невыполнимых задач и выбор модели.
4. Собрать собственные тренировочные задачи и полные траектории.
5. Зафиксировать транзитивные зависимости и проверить окончательные условия сдачи.

## Совместная работа

Каждый участник работает в своей ветке и предлагает изменения через pull request. Перед объединением проверяем, что агент запускается и решает согласованные примеры.

После первого рабочего прототипа можно разделить работу: один участник развивает инструменты и решение задач, второй — выбор задач, учёт бюджета и оценку результатов.

## Доступ к моделям

Код приглашения активируется в личном кабинете NeuralDeep. API-ключ берётся из кабинета и хранится локально, вне Git.

На проверке организаторы передают `LLM_BASE_URL` и `LLM_API_KEY` через переменные окружения. Программа должна использовать эти значения, а не адрес или ключ, зашитые в код.

## Формат сдачи

По предоставленному регламенту сдаётся ссылка на Git-репозиторий с программой, Dockerfile, зафиксированными зависимостями и инструкцией запуска. Организаторы собирают образ и запускают агента на скрытом наборе задач.

Точка входа соответствует примеру регламента: `/app/run_agent.py --tasks-dir /data/tasks`. Для приватного репозитория нужно дать доступ жюри `promsoft` и `madrugado`. Точный канал передачи ссылки пока не указан.

## Уточнения к регламенту

- Точный бюджет токенов и способ передачи его агенту.
- Окончательный формат сохранения ответов и рабочая папка задачи: общий файл или `answer.txt`, корень каталога задачи или `workspace`.
- Лимит CPU: в тексте указано 4 ядра, в примере запуска — 8.
- Точная дата и время закрытия сдачи, а также куда отправлять ссылку на репозиторий.
