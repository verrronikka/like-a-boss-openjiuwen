# Сравнение планировщиков 9 ноября 2026

Один парный опыт на одних и тех же 40 синтетических задачах validation, не использованных для настройки методов. Всего в этой части 32 решаемые и 8 нерешаемых задач; максимально доступная награда за решаемые — 141. Семейства validation не входят в train/calibration. Полный набор из 200 задач не прогонялся через API.

## Условия

- Модель: `qwen3.8-27b-noreason`, API NeuralDeep через openJiuwen, проверки решаемости включены.
- Два отдельных запуска на свежих копиях с одинаковыми входами; метки и эталоны контейнеру агента не монтировались.
- На каждый запуск: `--budget 10000 --task-budget 4000 --max-steps 12 --max-output 2048 --time-limit 900`.
- Docker: CPU 4, RAM 16 GB, только копия `tasks` доступна для записи; проверялка запускается отдельно без сети.
- Планировщик `density` — прежняя сортировка награда / оценка затрат. `knapsack` — динамическое программирование с шагом 10 и запасом затрат 25%, с пересчётом после каждой попытки.
- SHA256 исходных 200 задач: `29966a3e394c6af25cd7955b51cf5358925852d6b3de1d603a654de43bd76db8`.
- SHA256 входов validation обоих запусков: `4a3570c5a7e71825ed7b52641de30e24aa0bf9f4d0a6be4f5573102bc319dc54`.

## Измерения

| Метрика | density | knapsack |
| --- | ---: | ---: |
| Баллы из 141 | 99 | 101 |
| Правильно решены из 32 | 17 | 18 |
| Осознанно пропущены нерешаемые из 8 | 6 | 6 |
| Нерешаемые без окончательного решения | 2 | 2 |
| Неверные ответы на нерешаемые | 0 | 0 |
| Ложные пропуски решаемых | 0 | 0 |
| Всего взвешенных токенов | 9779,5 | 9839,0 |
| Из них на нерешаемые | 1391,6 | 1406,7 |
| Задачи с фактическим расходом API | 25 | 25 |
| Время контейнера, секунд | 192,6 | 200,2 |

Расход считается как вход / 10 + выход; проверки решаемости включены в эти числа. Оба запуска уложились в установленный лимит. Награда за правильный пропуск равна нулю.

У `density` в отчёт попали все 40 задач: 17 `submitted`, 6 `skipped`, 2 `budget_limit`, 15 `review_limit`. Последние 15 не вызвали API из-за недостаточного остатка для предварительной проверки; запись о них не означает полноценную попытку. У `knapsack`: 18 `submitted`, 6 `skipped`, 1 `budget_limit`, 15 `unattempted`; остановка `planner_no_fit`. Эти невыбранные задачи не засчитываются как распознанные нерешаемые. В обоих запусках положительные задачи без ответа получают ноль баллов.

## Вывод и ограничения

Рюкзак получил на 2 балла больше при расходе на 59,5 токена больше. Один запуск не отделяет эффект порядка задач от случайности генерации модели, поэтому `density` остаётся режимом по умолчанию. Подгонка коэффициентов по этой validation-части после измерения не выполнялась.

Это простые шаблонные примеры, а не независимые реальные проекты и не финальные задачи организаторов. В validation только четыре семейства. Оба режима не завершили часть задач при малом бюджете; это не проверка способности решить все 200. По этим результатам нельзя обещать такой же процент на скрытом наборе или при бюджете 100000.

Точная оптимальность рюкзака относится только к округлённым предполагаемым затратам. Стоимости пока заданы эвристикой; модель вероятности успеха и регрессия расхода не обучались. Следующий содержательный шаг — собрать измерения на train, откалибровать прогноз на calibration и оценить на новых семействах, сохранив эти результаты как опубликованный диагностический опыт.
