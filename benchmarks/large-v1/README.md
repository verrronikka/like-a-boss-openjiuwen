# Расширенный синтетический набор и математическое планирование

Набор v1 содержит **200 задач: 160 решаемых и 40 нерешаемых**, по 50 задач каждого из четырёх разрешённых типов. Это 20 шаблонных семейств с вариациями чисел и фактов, а не 200 независимых реальных проектов.

## Разделение по семействам

| Split | Задач | Нерешаемых | Назначение |
| --- | ---: | ---: | --- |
| train | 120 | 24 | Будущие измерения и настройка |
| calibration | 40 | 8 | Будущая калибровка прогнозов |
| validation | 40 | 8 | Отложенная проверка новых семейств |

Одно семейство находится только в одном split. Примеры train: остатки запасов, проценты, взвешенное среднее, прямые факты и временные записи, фильтрация CSV и баланс, преобразования списков. Validation: составной путь через владельца организации, расстояние нескольких участков, неизвестная цена в строке с нулевым весом и сортировка копии списка.

Метки `solvable`, `family`, `split`, эталонные ответы и референсные программы хранятся отдельно от `tasks`. Имена задач случайные, награды выбираются независимо от решаемости. Контейнер получает только `tasks`. Нерешаемые задачи требуют недостаточных данных или противоречат обязательным требованиям; отсутствующие несущественные данные не делают положительные случаи нерешаемыми.

Генератор: `scripts/build_large_benchmark.py`, seed `2026110903`. Архив `dataset-v1.zip` содержит только исходные задачи, проверочные оригиналы и labels.json; результаты прогонов, ключи и логи в него не включаются. Полный набор создан локально; не все 200 задач запускались через API.

## Использование

```powershell
py -3.12 scripts/build_large_benchmark.py --output runs/large-new
py -3.12 scripts/select_benchmark_split.py --source runs/large-new --output runs/validation-new --split validation
```

Монтировать в агент нужно `runs/validation-new/tasks`, а не всю папку набора. Проверялка `scripts/score_solvability.py` отдельно получает корень с `tasks`, `reference` и `labels.json`. Для каждого повторного прогона используйте свежую копию.

## Математический планировщик

`--planner density` сохраняет прежний порядок по награде / оценке стоимости и остаётся стандартным режимом. `--planner knapsack` включает экспериментальный 0/1-рюкзак:

```text
max sum(reward_i * x_i)
при sum(ceil(1.25 * estimated_cost_i / 10) * x_i) <= floor(remaining_budget / 10)
x_i принадлежит {0, 1}
```

Динамическое программирование находит оптимальное подмножество **для этих округлённых оценок**. После каждой попытки план пересчитывается по фактически оставшемуся бюджету. У выбранных задач сохраняется прежний порядок по плотности награды. Множитель 1,25 — запас, выбранный для эксперимента, не статистическая гарантия.

Оценка стоимости пока остаётся прежней эвристикой по типу и длине условия. Вероятность успеха не обучена и не подставляется из меток. Поэтому математическая оптимальность не гарантирует лучшего реального результата. При отсутствии подходящих по оценке задач планировщик сохраняет отчёт с `planner_no_fit` и перечнем невыбранных задач.

Например, при затратах 10, 20, 30 и наградах 60, 100, 120 с бюджетом 50 жадный выбор по плотности набирает 160, а рюкзак выбирает 20+30 и получает 220. Это иллюстрация с известными затратами, не результат агента на хакатоне. Реализация дополнительно проверена полным перебором на 70 малых случайных задачах.

## Неопределённость измерений

В проверялку добавлен интервал Уилсона. Даже 4 успешных отказа из 4 при допущении независимых испытаний дают нижнюю 95%-границу около 51%, а не гарантию 100%. Наши шаблонные случаи связаны между собой, а выбор задач зависит от бюджета, поэтому интервалы здесь только описательные и не являются сертификатом качества на финальном тесте.

Отчёт различает осознанные пропуски, неверные ответы, ложные пропуски, лимиты и невыбранные задачи. Невыбранная из-за бюджета задача не считается распознанной нерешаемой. Баллы считаются по всему заданному набору; стоимость дополнительных проверок включена.
