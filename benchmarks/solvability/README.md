# Проверка распознавания нерешаемых задач

Контролируемый локальный эксперимент, не официальный тест соревнования. По регламенту тренировочный набор собирают сами участники.

Первый прогон завершён: [результаты 9 ноября](results-2026-11-09.md). Решены 12/12 решаемых задач, осознанных пропусков нерешаемых — 0/4. На нерешаемые ушло 38,4% расхода. Поведение агента перед этим измерением не изменялось.

Затем добавлены проверка и подтверждение отказов: [сравнение исправления](results-review-2026-11-09.md). На первом наборе решены 12/12 и пропущены 4/4 нерешаемых; на контрольном — 8/8 и 4/4. Ложных пропусков в этих полных прогонах нет. Общий расход уменьшился на 12% и 36% соответственно.

## Набор

Всего 16 задач: восемь исходных решаемых примеров организаторов и четыре новые пары. В каждой паре одна задача решаемая, вторая не имеет точного решения при имеющихся данных. Доля нерешаемых — 25%.

| Тип | Что делает задачу нерешаемой | Решаемая контрольная версия |
| --- | --- | --- |
| Математика | Неизвестен начальный объём воды | Начальный объём указан |
| Поиск | В базе нет города штаб-квартиры нужной компании | Город присутствует в файле компании |
| CSV | В подходящей строке неизвестно количество единиц | Все подходящие значения известны; пропуск есть только в нерелевантной строке |
| Код | Два теста требуют разные результаты для одинакового входа чистой детерминированной функции | Тесты согласованы и проверяют разные входы |

Генератор: `scripts/build_solvability_benchmark.py`, seed `20261109`. Имена каталогов обезличены, награды выбраны случайно независимо от меток. Поле `expected` отсутствует во входах агента. Разметка и оригиналы для проверки находятся вне папки, монтируемой в контейнер агента.

Это небольшой специально сконструированный диагностический набор. Успех на нём не доказывает универсального распознавания нерешаемых задач. Инструкции агента перед первым экспериментом не меняются.

## Воспроизведение

Создать новый набор; существующая папка не перезаписывается:

```powershell
py -3.12 scripts/build_solvability_benchmark.py --output runs/solvability-new
docker run --rm --read-only --tmpfs /tmp:rw,size=2g --cap-drop ALL --security-opt no-new-privileges --cpus 4 --memory 16g --pids-limit 512 --env-file .env -v "${PWD}/runs/solvability-new/tasks:/data/tasks:rw" like-a-boss-openjiuwen:dev --tasks-dir /data/tasks --budget 20000 --task-budget 4000 --max-steps 12 --max-output 2048 --time-limit 900
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g -v "${PWD}/runs/solvability-new:/benchmark:ro" -v "${PWD}/scripts:/checker:ro" --entrypoint python like-a-boss-openjiuwen:dev /checker/score_solvability.py --benchmark-dir /benchmark
```

Первый контейнер видит только `tasks`, второй отдельно проверяет результаты без сети и без API-ключа. Для каждого повторения нужна свежая копия набора. Модель по умолчанию — `qwen3.8-27b-noreason`; запуск расходует квоту API.

## Метрики

Для проверки изменений предусмотрен дополнительный авторский набор `--suite heldout`: 12 новых задач (8 решаемых, 4 нерешаемых), созданных до изменения агента. В нём есть сокращение неизвестных, неоднозначность личности, неполный join таблиц и несовместимые числовые ограничения. Набор используется для повторных контрольных прогонов; после разбора обнаруженных ошибок он не является полностью нетронутым внешним тестом. Награды и метки также отделены от входов агента.

```powershell
py -3.12 scripts/build_solvability_benchmark.py --suite heldout --output runs/solvability-control-new
```

- Правильные решения на решаемых задачах и набранные за них баллы.
- Ложные пропуски решаемых задач.
- Осознанные пропуски нерешаемых: статус `skipped` и отсутствие `answer.txt`.
- Ошибочные ответы на нерешаемые: наличие файла ответа.
- Отсутствие решения по лимиту, ошибке или из-за невыбранной задачи — отдельная категория, не успешное распознавание.
- Общий расход и расход на нерешаемые задачи в эквиваленте выходных токенов.

Результат оценивается по точности решения и факту отказа. Текст причины пропуска сохраняется для ручного разбора; сам по себе красивый текст не считается доказательством правильного распознавания.
