# Первый эксперимент с нерешаемыми задачами

Дата: 9 ноября 2026. Модель: `qwen3.8-27b-noreason` через API NeuralDeep. Проверялось исходное поведение агента из коммита `cfbe36c`: инструкции и алгоритм решения перед экспериментом не менялись. Новыми были генератор, разметка и отдельная проверялка.

## Результаты

| Показатель | Результат |
| --- | --- |
| Набор | 16 задач: 12 решаемых, 4 нерешаемые |
| Решаемые задачи | 12 из 12 прошли проверку |
| Ложные пропуски решаемых | 0 |
| Осознанные пропуски нерешаемых | **0 из 4** |
| Неверные ответы на нерешаемые | 3 |
| Нерешаемые без решения из-за лимита | 1 |
| Локальные баллы за решаемые | 30 из 30 |
| Общий расход | 12 947,6 |
| Расход на нерешаемые | 4 967,0 — **38,4%** общего расхода |
| Расход на решаемые | 7 980,6 |
| Время агента | 189,3 секунды |

Расход указан в эквиваленте выходных токенов: вход / 10 + выход. Максимум 30 баллов относится только к этому набору со случайными наградами; его нельзя сравнивать напрямую с 20 баллами исходных восьми примеров. Пропуск нерешаемой задачи не даёт баллов. Для обнаружения недостатка данных тоже нужны токены, поэтому не весь расход 4 967 можно устранить.

## Что произошло с нерешаемыми задачами

| Тип / ID | Нехватка или противоречие | Поведение агента | Расход |
| --- | --- | --- | ---: |
| Математика / `case_3643` | Неизвестен начальный объём воды | Ответил `45`, хотя известна лишь разница добавления и удаления | 217,7 |
| Поиск / `case_7107` | В базе нет города нужной компании | Ответил `Berlin` — это город другой компании | 916,8 |
| CSV / `case_7942` | В подходящей строке неизвестно количество единиц | Ответил `8`, посчитав только известное значение; точный итог не определён | 479,3 |
| Код / `case_4564` | Для одинакового входа чистой функции тесты требуют 5 и 6 | Дошёл до ограничения бюджета задачи, файл ответа не создал | 3 353,2 |

В задаче на код модель попыталась реализовать определение вызывающего теста через стек вызовов, хотя условие прямо запрещало изучать вызывающий код и требовало чистую детерминированную функцию. Такая подстройка нарушает условие; мы не считаем её решением. Статус `budget_limit` без файла ответа означает остановку по лимиту, а не осознанное распознавание невозможности.

Все решаемые контрольные версии пройдены, включая CSV с пропущенным значением в нерелевантной строке и согласованные тесты функции.

## Методика

- Восемь исходных решаемых примеров плюс четыре пары «решаемая / нерешаемая», по паре каждого типа.
- У каталога задачи обезличенное имя, `reward` выбран независимо от решаемости.
- Во входном `task.json` отсутствуют эталоны и метки решаемости.
- Контейнер агента получает только папку `tasks`. Разметка `labels.json` и проверочные оригиналы `reference` находятся вне его монтирования.
- Отдельный контейнер без сети проверяет результаты и неизменность тестов.
- Исходные примеры организаторов не изменялись.
- В Docker прошли 14 автоматических тестов, включая воспроизводимость генератора и раздельный учёт пропусков, ошибок и незавершённых задач.

Параметры: `--budget 20000 --task-budget 4000 --max-steps 12 --max-output 2048 --time-limit 900`. Ограничения контейнера: 4 CPU, 16 ГБ RAM, read-only корень и временная папка `/tmp`.

## Вывод и следующий шаг

Прототип решает положительные примеры, но наличие инструмента `skip_task` само по себе не обеспечивает корректный отказ. Следующее улучшение — явная проверка достаточности данных и согласованности требований перед вычислением или исправлением кода, запрет догадок вместо неизвестных значений и ограничение бесплодных повторов. После изменения поведения нужно повторить контрольные пары и проверить новые, заранее отложенные случаи.

Это один прогон на четырёх специально сконструированных нерешаемых задачах. Он выявляет конкретные проблемы, но не оценивает качество на всём скрытом финальном наборе. Qwen в этом эксперименте не дообучалась.
